# Проверки и границы результата

[English](../en/testing.md) · [Главная](../../README.md)

Публичный выпуск: FlashOS 2026.09.09.3, установщик 1.0.2. Ниже указано, что проверялось, и чем эти проверки ограничены. Они не означают работу на любом ПК.

## Автоматические проверки

В Debian выполнен `python3 -m unittest discover -s tests -q`: **167 тестов, без ошибок, 14 проверок Windows/Qt пропущены на Linux**. В Windows отдельно выполнены **48 тестов установщика**, включая завершение дочернего процесса записи, проверку устройства, запрет опасных целей, повреждённый набор файлов, проверки MBR/GPT/EFI, удержание блокировки до очистки, текстовый курсор, фокус и показатели прогресса.

Проверка live-системы сверяет каждый файл `src/*.py` с содержимым squashfs и подтверждает отсутствие гостевых тестовых служб и сценариев в пользовательском образе. В подготовленной системе проверены 70 используемых команд, Tk 8.6 и обработка аргументов smartctl. Добавлены проверки очистки служебных данных сборочного ПК, включая отказ работать с неверным корнем и с выходящими наружу ссылками.

Тест Qt использует вымышленные флешки. Он проверяет клавиатуру, подтверждение удаления, несколько устройств, прогресс, ошибки и окно при 640×480, 800×600, 1000×800 и 1280×900; отдельно проверен масштаб 200%. В итоговом EXE проверены выделение первой записи журнала стрелками через TextPattern, переход F6 к состоянию, переключение разделов справки стрелками, Tab к её тексту и движение по таблице состава EXE. Проверен запуск единственного EXE из папки с русским именем. Это не заменяет пользовательское испытание с NVDA, JAWS или экранным диктором; озвучка NVDA на слух отдельно не оценивалась.

Перед публикацией проверяются ссылки документации, состав отслеживаемых файлов, отсутствие сгенерированных образов и похожих на ключи строк в Git, контрольные суммы архивов и полнота исходных пакетов Debian. GitHub Actions повторяет безопасные модульные проверки. CI не записывает физические диски.

## Загрузка и восстановление

До подготовки публичной упаковки система 2026.09.09.2 прошла 108 модульных Linux-тестов и 42 сценария в QEMU для инструментов/восстановления. Отдельно проверялись BIOS, UEFI, Secure Boot с подготовленным состоянием ключей, виртуальные звуковые устройства, создание, проверка и восстановление резервных образов. Это история испытаний исходной функциональности, а не новый полный прогон каждого сценария на версии .3.

Выпуск .3 сохраняет инструменты и загрузочное ядро; изменены номер версии и очистка machine-id, сетевого файла сборочной среды и журналов. Повторно проверен выход нового образа в меню QEMU: BIOS с HDA-аудио и UEFI Secure Boot с USB-аудио и ранее подготовленными ключами. Результат проверки запуска итогового EXE указан в описании релиза. Запись звука в VM подтверждает наличие сигнала, но сама по себе не доказывает разборчивость речи.

## Физическая флешка

Для установщика 1.0.2 повторно выполнены форматирование exFAT (20,56 с), установка с проверкой (238,56 с) и отдельная проверка (37,30 с) на одной Kingston DataTraveler 3.0 объёмом 64 ГБ. Физические операции выполнены локальным испытательным сценарием через тот же модуль записи, который включён в EXE. Проверены SHA256 файлов, разметка и BIOS/UEFI-структуры. Разметка внутреннего NVMe не изменилась.

После физического испытания уточнялись только отображение и навигация GUI; модуль записи, его зависимости и встроенный комплект остались идентичными испытанным. Финальный EXE отдельно проверен интерактивно. Другие ПК и физический USB 2.0 не испытывались; времена выше относятся только к этому прогону. Холодный запуск на физическом ПК после перезагрузки не выполнен. Личные журналы, серийные номера и резервная копия флешки не публикуются. См. [исходный аудит установщика](installer-audit-2026-09-10.md).

## Что остаётся проверить на оборудовании пользователя

Первый запуск Secure Boot с неподготовленными ключами; доступность меню прошивки; встроенный звук конкретного ПК; USB-мосты и SMART; реальные сочетания прошивок, контроллеров и дисков; сторонние установщики ОС и их скринридеры. Память, занятая FlashOS и ядром, остаётся вне memtester. Неполный SMART или отсутствие ошибок не равны доказанной исправности оборудования.

Если нашли ошибку, [сообщите о ней](../../CONTRIBUTING.md), указав версию, оборудование, клавиши и ожидаемый результат.
