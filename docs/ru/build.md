# Сборка FlashOS и установщика

[English](../en/build.md) · [Главная](../../README.md)

Сначала собирается загрузочная Linux-среда, затем она упаковывается в EXE Windows. Это инструкция по сборке из исходников, а не обещание побайтового совпадения результата: состав Debian-репозиториев, метаданные компилятора и время сборки могут меняться. Версии опубликованного выпуска и контрольные суммы находятся в `metadata` и архивах релиза.

## Linux-среда

Клонируйте репозиторий и выберите нужный тег. Используйте отдельную Debian 13 x86-64 в виртуальной машине или WSL. Сценарии создают систему в `/opt/flashos-rootfs`; не направляйте их на корень работающей ОС. Для сборки и архивов понадобится не менее 20 ГБ свободного места.

Из корня проекта выполните:

```sh
python3 tools/fetch-build-inputs.py
sudo bash build/setup-builder.sh
sudo bash build/build-system.sh
```

Загрузчик файлов сверяет SHA256 закреплённых Ventoy, SOF и текстов лицензий. Подготовке нужен интернет и root внутри сборочной среды. Списки пакетов находятся в `build/build-system.sh`, `install-admin.sh` и `install-recovery.sh`. Сборщик получает указанную ревизию RHVoice с подмодулями, устанавливает SOF, копирует `src` и `boot`, убирает идентификаторы и журналы сборочного ПК, создаёт initrd/squashfs и правит конфигурацию GRUB Ventoy. Подписанные EFI-файлы сохраняются исходными.

Результат: `dist/usb`, `dist/boot`, `dist/ventoy.disk.img.xz`, `dist/packages.tsv`. Не кладите в дерево упаковки свои ISO, настройки, резервные копии и отчёты. `tools/package-public-docs.py` копирует только публичную документацию. Тестовые ISO храните отдельно.

Для сборки EXE с готовой системой скачайте `FlashOS-2026.09.12.1-system.zip` из [этого релиза](https://github.com/andreykadelite/flashos-voiceboot/releases/tag/v2026.09.12.1-installer-1.0.4), сверьте SHA256 и распакуйте архив в корень исходников того же тега. Он заполнит дерево `dist`. Флешку подготавливает EXE: ZIP содержит файлы для сборки, поэтому записывать его через Rufus или dd нельзя.

Если вы изменили код FlashOS, выполните `build/repack-system.sh` в подготовленной Linux-среде. Сценарий `tools/verify-toolkit-build.py` сравнит исходники с файлами внутри squashfs и сохранит SHA256 образа. Упаковка остановится, если версия системы, образ или исходники не совпадут с отчётом. В архив готовой системы этот отчёт уже включён.

Полная сборка Linux обращается к текущим индексам trixie/backports. Для пересборки старых Debian-пакетов используйте точные `.dsc`, исходные архивы и патчи Debian из архива исходников релиза, команды `dpkg-source -x` и `dpkg-buildpackage` в соответствующей Debian-среде. В `metadata/debian-sources.json` перечислены исходные файлы и SHA256. У сторонних проектов в архивах есть собственные инструкции. Пересборка EFI не воспроизводит подпись Debian или Ventoy: для изменённых загрузчиков нужна своя цепочка доверия.

## EXE Windows

Нужна Windows x64 и Python **3.12.10**. Установите обычный CPython в `build/installer/python312`, включая pip, файлы разработки и `LICENSE.txt`. Минимального embeddable ZIP недостаточно. Сценарий использует именно этот отдельный интерпретатор.

```powershell
& .\build\installer\python312\python.exe -m pip install -r installer/requirements-build.txt
& .\build\installer\python312\python.exe tools/fetch-build-inputs.py
.\tools\Build-Installer.ps1 -Mode onefile
```

Закреплены PySide6/Qt **6.11.2**, Nuitka **4.2.1**, zstandard **0.25.0** и ordered-set **4.1.0**. При первой сборке Nuitka скачивает свой MinGW; для опубликованного EXE использован MinGW 15.2. Сценарий упаковывает систему без дубликатов, записывает хеш манифеста в `installer/_release.py`, запускает тесты установщика и компиляцию. Результат — `release/FlashOS-Setup.exe` и SHA256.

Генератору `tools/build-installer-payload.py` нужны готовое дерево `dist`, Windows-архив Ventoy, публичные документы и лицензии. ISO исключаются. Исходный модуль записи — `installer/engine.ps1`; после его изменения `_release.py` должен быть сгенерирован заново. На целевом ПК Python не нужен: он встроен в EXE.

## Изменённые Qt и PySide6

DLL подключаются динамически. Разрешено менять LGPL-библиотеки и исследовать работу приложения для отладки таких изменений. Исходники использованных Qt base и PySide/Shiboken приложены к релизу.

Соберите совместимые Qt/PySide6 по инструкциям из их архивов, установите полученные библиотеки и wheel в выделенный Python, затем выполните `Build-Installer.ps1 -Mode standalone`. В `build/installer/nuitka/entry.dist` можно заменить DLL Qt/PySide/Shiboken и плагины платформы/стиля согласованным совместимым набором и запустить EXE из этой папки. Для одного файла повторите сборку с `-Mode onefile` в изменённой среде. Проверка встроенных системных данных не запрещает замену Qt или пересборку приложения. Ключ издателя FlashOS для запуска изменённого установщика не требуется.

## Проверки без записи на физические диски

```sh
python3 -m unittest discover -s tests -v
python3 tools/check-publication.py
```

В Windows: `python -m unittest discover -s tests -p 'test_installer*.py' -v`. После подготовки зависимостей и встроенного набора `python tools/check-installer-qt.py` проверяет клавиатуру и размеры окна на вымышленных USB-устройствах. Результаты пишутся в `dist`, а не на флешку.

Для проверки загрузки распакуйте проверенный Linux-архив Ventoy в `tools/ventoy-1.1.17`. В Linux-среде выполните:

```sh
sudo python3 tools/make-test-disk.py --size-gib 4
python3 tools/vm.py bios
python3 tools/vm.py status
python3 tools/vm.py quit
```

Создаётся только файл `dist/flashos-test.img`; QEMU получает его, не физические диски. Одновременно запускайте одну VM. Режимы `uefi` и `secure` используют OVMF согласно `tools/vm.py`; регистрация ключа — отдельная настройка. Гостевым тестам восстановления нужны тестовые образы из соответствующих сценариев. Приёмочные скрипты с записью на настоящий USB не должны попадать в CI.

## Публикация изменённой версии

Сохраните имя автора и лицензию, отметьте свои изменения. Проверьте условия голосов и прошивок, приложите соответствующие исходники, уберите личные данные из live-среды и набора файлов, проведите проверки и прикрепите EXE, систему, исходники и хеши к релизу. `tools/export-system.py` создаёт ZIP системы. Большие сборочные файлы и личные копии USB не включайте в Git.
